## 已证实的行为

- `crates/reference-host/src/http.rs::open` 在发送前持久化审计。`crates/reference-host/src/before_send.rs::body` 把 `bytes` 正文生成结构化 `body` 和按输入顺序排列的 `text`。2.1.4 处理 HTTP 请求目标 URL 的 query，正文只经过凭据库已知值替换。真实 HTTP 收到原始编辑 JSON，未登记签名出现在持久审计中。
- 用 `body=media` 发送同一 JSON 时，审计仅记录句柄对应的摘要。`crates/media/src/lib.rs` 在 `write` 时写 staging，`finish` 后发布内容寻址对象，`release` 后已完成对象仍含签名。原片二进制继续使用媒体句柄，包含授权 URL 的 JSON 使用小型内存正文。
- 发布版 CLI/worker 探针把合成地址作为普通输入，远端收到完整地址，`input.invocation.json`、worker 的 `before-send.jsonl`、host-channel 持久记录均命中签名，当前回执未命中。实际接入先传原片句柄，再在调用内取得签名。`Invocation`、`uploadRef`、checkpoint、错误文本和回执只传可安全保留的信息。

## 333 审核决定

- H01，审计边界。URL 识别只作用于小型 bytes 正文中的独立 JSON 字符串值。拒绝把带原始空白的自然语言识别为独立 URL。结构化正文与有序文本使用同一规则。既有网络 URL 处理、非 JSON 正文、multipart 和媒体摘要继续原行为。
- H02，完整链。SDK 本仓测试实际 HTTP 和 before-send ACK。调用方用独立 WASM 探针和真实 worker 依次上传、提交、保存合成任务号和恢复查询。签名由上传响应生成并在请求内传递，输入诊断和恢复数据只含安全字段。使用拒绝 ACK 与已发送但未受理两条故障分支复验。显式回放录制和真实云端取片分别记账。
- 验收档位由模型依据用户要求确定为定向 SDK + 真实 worker 回环联合验证。版本 2.1.5 经检查可用，保持协议 2 / WIT 2.0.0。用户要求暂跳过真实可灵取片，工作台继续遵守 T24 的双前置。
