# 未知受理在线核验与持久请求域

用户主程序需求：长片任务的同步语音提交窗口崩溃后，不能从 `acceptance_unknown` 自动重发，也不能永远无法找回已受理成果。本批固定 SDK `48a93b7`，已 fetch，工作区干净。六操作保留，仅在正式 `probe` 增加语义；现有 operator-reviewed 离线 resolve 不冒充在线机制。

## 文件级原子计划

1. `schemas/submission-resolution.schema.json`、`schemas/control-operations.schema.json`、`schemas/checkpoint.schema.json`、`protocol/host-feature-catalog.json`：新增无 WIT imports 的 `submission-resolution-v1`。在线 identity probe 返回持久 storeId 和当前 instanceId；SDK 在提交开始之前冻结到 prepared checkpoint。在线 resolution 必须携带原 requestId/requestDigest/expectedRevision/package/binding/configuration/submissionScope，返回 accepted、rejected 或 unknown。
2. `crates/validator/src/submission_resolution.rs` 及 registry/result 接线：检查请求结果严格配对、scope 恒定、accepted 仅标准异步受理回执、拒绝必须是同一持久请求域的原子 tombstone 并保证晚到 POST 永久被拒。404、超时、换库/丢库、旧包/无原 scope 均不能认证未受理。
3. `crates/reference-host/src/session.rs`、`dispatch.rs`：复用唯一 checkpoint store 和 CAS。异步 submit 前自动 identity，scope 落盘后才 begin_submit；resolution 通过原包与原 binding 恢复 session，accepted 重新校验原操作 resume schema 后原子接回 query，rejected 原子关闭原请求，unknown 不改变受理状态。任何路径均不得再次 submit。
4. `crates/tools/src/run.rs`：probe 能显式绑定原 root checkpoint；不新增 CLI 私有恢复状态机。`schema_registry` 和文档/消费输入同批收录。
5. 扩展既有 recovery/dispatch 测试：冷恢复 accepted、tombstone拒绝、原实例改变但持久域一致、不同域、不同digest/revision、无feature/旧checkpoint、并发CAS和迟到原结果冲突。验证实际 adapter durable job，不把模拟通过等同完整 TTS 冷恢复。
6. 主仓通用 `adapter_host/v2` 在 query 前对 unknown 且正式 feature/scope 的原包发 probe，然后重读原 CAS checkpoint继续 query；不得按厂商名、不得修改历史 frozen。编译中的主仓保持冻结，改动先置 logs 候选 patch，根授权后应用。新包安装沿统一当前引用迁移 owner 核 SavedDubbingRole，历史任务包继续保留。

实施补充：根确认候选编译完成后已解冻主源码。普通语音/preview 沿 `process_speech_session.rs` 复用原 SDK per-request 工作区，`crates/tools/src/session_inspect.rs` 提供只读公开投影；产品不读取 SDK 私有表。`transport::Control::child` 保持父取消向下传播、子清理不取消父流程。共享 runtimeRoot 安装维护、已受理取消观察、当前角色引用迁移由主仓同批独立 owner 实施。

## 自审与交付边界

- durable storeId 在首个真实提交前冻结；进程重启可换 instanceId，但远程换库不能凭新空库拒绝原请求。
- adapter POST 必须携带 expectedStoreId，与 resolve 共用原子记录锁和 tombstone；成功生成的媒体和原请求引用持久保存。
- HostPort、网络、包身份、配置摘要、受控媒体与 CAS owner 全部复用，不新造调度器，不以 error code 推导未受理。
- 源码、SDK定向构建/测试、公开完整可下载产物、主程序新 EXE 冷恢复分别记实。未跑不得报通过。
